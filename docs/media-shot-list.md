# Burette: план скриншотов и записей для сайта

Обновлено: 13 сентября 2026. Это план будущей съёмки, не отчёт о готовых материалах.

## Что уже есть

Главное превью — живой браузерный workspace в MacBook. В цикле шесть файлов:
7RPZ.pdb, caffeine.cif, 1HTB.pdb, bimp.v000.xyz, buckyball.xyz, caffeine_cell.xyz.
Каждая сцена длится 32 секунды; камера плавно поворачивается и приближается,
BIMP проигрывает траекторию. Ниже 640 px используется статичное превью.
Для этих поворотов дополнительные записи не нужны. Записи ниже показывают
конкретные рабочие действия, которые герой страницы пока не объясняет.

## Второй проход — после проверки в актуальной нативной сборке

Эти сюжеты — кандидаты. До размещения проверить доступность именно в версии,
которую посетитель скачивает, нужные движки и ограничения форматов.

- **Суперпозиция белков:** два белка до и после выравнивания, отображаемая метрика результата → отдельная карточка сравнения.
- **Плотность / орбитали / фармакофор:** по одному ясному примеру, читаемая легенда → карточки дополнительных научных данных.
- **Спектры:** реальный файл, выделенный пик и его подпись → карточка спектров.
- **xTB / CREST / PRISM:** исходная геометрия → параметры → завершённый расчёт → результат оптимизации / конформеры / отбор. Снимать короткий путь с готовым результатом; не создавать впечатление мгновенного расчёта.
- **FEP / GraphML, Mesoscale, MVS Stories:** отдельные короткие сюжеты только при подтверждённом рабочем сценарии; сначала для документации.
- **Передача во внешнее приложение:** Open in ChimeraX / PyMOL / Maestro → тот же файл в установленном приложении. Снимать на Mac, не в браузерном демо.
- **iPhone:** реальное приложение на устройстве или явно обозначенный Simulator. Отдельный материал, не мобильный вид веб-лендинга; ясно указать способ доступности приложения.

## Единый стандарт съёмки

- Реальный интерфейс Burette, стиль Illustrative для молекулярных сцен. Для xyzrender показать его собственный результат и назвать движок.
- Один сюжет — одна задача и видимый результат. В начале и конце выдержать 2–3 секунды.
- Скриншоты — светлая и тёмная темы с одинаковым файлом, ракурсом и расположением панелей.
- Убрать случайные hover-подсветки, подсказки, уведомления и посторонние окна. Меню оставлять только в момент выбора действия.
- Единый фон и масштаб. Окно приложения полностью помещается в кадр, ключевые подписи читаются без увеличения.
- Исходники: PNG и MOV/MP4 в 1440p или Retina, 30 fps достаточно; голос не обязателен. Оригиналы хранить вне репозитория.
- Для сайта: оптимизированный MP4/WebM, постер WebP/AVIF, отдельная композиция для телефона при необходимости. Не пытаться втиснуть весь desktop UI в узкую вертикальную запись.
- Видеофайлы для сайта размещать в `public/assets/` (либо согласованном медиахранилище), подключать по клику/видимости; одновременно проигрывать один ролик.
- Предлагаемые имена: `quick-look-demo`, `collection-filter-export`, `ketcher-edit`, `chemical-space-select`, `selection-measure`, `sdf-all-align`, `trajectory-playback`, `figure-svg-export`, `burette-agent-workflow` плюс суффиксы `-light`, `-dark`, `-poster`.

## Как проверить материал перед размещением

В кадре видно, какой файл открыт, что пользователь сделал и что получил.
Заявленная функция работает в показываемой поверхности: Mac, Quick Look,
браузерное демо или iPhone. Ожидание расчётов и загрузки не вырезано так,
чтобы искажать скорость. Сохранённый файл действительно открывается.
Сначала выбрать итоговый кадр, затем под него править подпись на сайте.
