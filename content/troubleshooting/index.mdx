# Troubleshooting

Start with the surface that is failing. A Finder registration reset will not fix a calculation engine or an unsupported file.

| Problem | First check |
| --- | --- |
| Finder shows no molecular preview | Open Burette once, then follow [Quick Look troubleshooting](/docs/troubleshooting/quick-look). |
| One file fails in both Finder and the app | Check its format and required companion files in [supported formats](/docs/formats). Try a small known-good file of the same type. |
| An external renderer is unavailable | Check the selected renderer and executable in Settings. See [engines](/docs/engines). |
| xTB, CREST, or PRISM cannot start | Run the engine’s runtime check and inspect its executable path and version. |
| A native calculation fails | Read the job report for runtime readiness, backend, scope, and per-molecule errors. See [native compute](/docs/workflows/native-compute). |
| A website action cannot open a local app or run native compute | Use the installed Mac app; the browser demo has a smaller scope. |

## Collect useful diagnostics

Use **Open Logs Folder** or **Export Diagnostics** in the command palette. The diagnostics bundle is created locally; exporting it does not automatically submit an issue.

Before sharing a bundle, review it for filenames, paths, and other information you do not want to publish. Include the Burette version, macOS version, failing action, and error message. Attach a minimal example file only when you can share it.

[Report an issue](https://github.com/SergeiNikolenko/Burette/issues).
