# Install Burette

Every Burette release ships desktop packages for **macOS**, **Windows**, and **Linux** on [GitHub Releases](https://github.com/SergeiNikolenko/Burette/releases/latest).

## macOS (Apple Silicon, macOS 12+)

Install from the Homebrew tap:

```bash
brew tap SergeiNikolenko/burette
brew install --cask burette
```

Check the installed cask version:

```bash
brew info --cask SergeiNikolenko/burette/burette
```

Or install manually from GitHub Releases:

1. Open the [latest release](https://github.com/SergeiNikolenko/Burette/releases/latest).
2. Download the `Burette-<version>.dmg` or `Burette-<version>.zip` file.
3. Open the DMG or unzip the archive.
4. Move `Burette.app` to your `Applications` folder.
5. Open Burette once from `Applications` to register the app and Finder Quick Look extension.

Signing and notarization depend on the release build. If macOS blocks the downloaded app, first confirm it came from the official release page. Follow the first-launch instructions for that release; macOS may offer approval in **System Settings → Privacy & Security**. Do not disable Gatekeeper globally.

If Finder previews do not appear after install, open Burette's command palette
and run **Reset Quick Look**. **Open Logs Folder** and **Export Diagnostics**
are available there as well.

## Windows (Windows 10 and 11, x64)

1. Open the [latest release](https://github.com/SergeiNikolenko/Burette/releases/latest) and download `Burette_<version>_x64-setup.exe`.
2. Run the installer. It installs per user into `%LOCALAPPDATA%\Burette` without administrator rights, registers molecular file associations, and adds Start menu entries.
3. Burette renders through Microsoft Edge WebView2, which is built into Windows 11 and current Windows 10 (and fetched automatically if missing).
4. Release installers are not code-signed yet, so Windows SmartScreen asks for confirmation on first run (**More info → Run anyway**).

Data paths: settings and workspaces live in `%APPDATA%\com.local.BuretteV10`; caches, logs, and optional managed runtimes live in `%LOCALAPPDATA%\com.local.BuretteV10`.

## Linux (x86_64, WebKitGTK 4.1)

Download the package for your distribution from the [latest release](https://github.com/SergeiNikolenko/Burette/releases/latest):

```bash
sudo apt install ./Burette_<version>_amd64.deb           # Debian 12+, Ubuntu 22.04+
sudo dnf install ./Burette-<version>-1.x86_64.rpm       # Fedora 39+, RHEL, openSUSE
chmod +x Burette_<version>_amd64.AppImage && ./Burette_<version>_amd64.AppImage
```

The `.deb` and `.rpm` packages declare WebKitGTK 4.1 as a dependency and install desktop entries plus molecular MIME associations (`/usr/share/mime/packages/burette.xml`). SHA-256 checksums are attached as `Burette-<version>-linux.sha256`.

## Updates

- **macOS (Sparkle / DMG / ZIP):** Use **Check for Updates** in Burette to update in place, or install the latest archive.
- **macOS (Homebrew):**

```bash
brew update
brew upgrade --cask burette
```

- **Windows and Linux:** **Help → Check for Updates** checks GitHub Releases and opens the release page for the latest installer or package. Re-installing keeps your project files and settings.

## Codex plugin and local MCP

The optional Codex integration lives in the same [Burette repository](https://github.com/SergeiNikolenko/Burette) as the app. It bundles workflow skills with typed MCP tools for opening, observing, and controlling a local molecular workspace.

Install Git, Bun, and Codex first. Clone the repository and run the plugin installer:

```bash
git clone https://github.com/SergeiNikolenko/Burette.git
cd Burette
bun run install:plugin
```

Restart Codex after installation, then mention `@Burette` or select Burette from Plugins. See [Codex Plugin and MCP](/docs/plugin) for the tool surface, security boundaries, and source links.

## Optional local calculation engines

The Burette application does not bundle xTB, CREST, or PRISM. Install only the engines needed for your local workflow:

```bash
pixi global install xtb
pixi global install crest
uv tool install prism_pruner
```

These commands require Pixi or uv to be installed first. For xTB, Settings can instead install a Burette-managed environment when Pixi or Conda is available. Check each executable, then use the matching runtime check in the desktop inspector. See [xTB calculations](/docs/workflows/xtb) and [CREST and PRISM](/docs/workflows/crest-prism).
